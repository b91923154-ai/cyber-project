1. PROJECT KYA HAI AUR KYU BANAYA GAYA HAI? (Introduction)
--------------------------------------------------------------------------------
CyberShield ek modern "Web Vulnerability Scanner as a Service" platform hai. 
Simple shabdon mein kahein toh: 
Ye ek aisi website/tool hai jahan koi bhi web developer ya company apna domain 
(jaise example.com) daal kar ye check kar sakti hai ki unki website kitni secure hai, 
kya usme koi security kamzori (vulnerability) toh nahi hai, aur use theek kaise karein.

Aam taur par student projects ya market ke free scanners mein 3 badi galtiyan hoti hain:
1. Koi bhi kisi ki bhi website (jaise google.com) scan karke attack tool ki tarah use karta hai.
2. Scanners khud hi hack ho jaate hain (SSRF attack se internal network leak ho jata hai).
3. False Positives (galat warnings) itni zyada hoti hain ki developers pareshan ho jaate hain.

CyberShield ko inhi sabhi problems ko solve karne ke liye "SAFE BY DESIGN" philosophy 
par banaya gaya hai.

2. TWO-TIER SCAN SYSTEM (Kaise Kaam Karta Hai?)
================================================================================
CyberShield pure scanning process ko 2 alag-alag tiers mein baant-ta hai taaki 
legal aur security issues na aayein:

--------------------------------------------------------------------------------
TIER 1: BASIC SCAN (Passive & Non-Intrusive — Har kisi ke liye open)
--------------------------------------------------------------------------------
Is tier mein hum target website par koi attack ya aggressive request nahi bhejte.
Ye wahi cheezein check karta hai jo ek normal browser (Chrome/Edge) website open 
karte waqt dekhta hai:

a) HTTP Security Headers:
   - Strict-Transport-Security (HSTS): Check karta hai ki browser hamesha HTTPS use kare.
   - Content-Security-Policy (CSP): XSS attack se bachata hai.
   - X-Frame-Options: Clickjacking (fake frame ke peeche click karwana) ko rokta hai.
   - X-Content-Type-Options: MIME sniffing attacks ko rokta hai.
   - Referrer-Policy & Permissions-Policy: Sensitive URL leak aur camera/mic access rokta hai.

b) Cryptographic / TLS Handshake:
   - TLS Version: TLS 1.3 ya 1.2 use ho raha hai ya koi purana insecure version.
   - SSL Certificate Expiry: Certificate kitne din baad expire hoga (countdown).
   - Cipher Suite: Encryption kitna strong hai.
   - SHA-256 Fingerprint: Certificate ka digital thumbprint verify karta hai.

c) Cookie Security:
   - Check karta hai ki session cookies mein 'Secure', 'HttpOnly', aur 'SameSite' 
     flags lage hain ya nahi.

d) Supply-Chain & JavaScript Libraries Check:
   - Subresource Integrity (SRI): Agar website bahar se CDN script load kar rahi hai, 
     toh kya usme SRI hash check hai? Agar nahi, toh supply-chain attack ho sakta hai.
   - Outdated JS Libraries: Page ke code ko scan karke check karta hai ki purana 
     vulnerable jQuery, Bootstrap, AngularJS, ya Lodash toh use nahi ho raha (with CVE IDs).

e) DNS & Email Spoofing Defense:
   - SPF (Sender Policy Framework) & DMARC records check karta hai. Agar ye missing 
     hain, toh hackers aapki company ke email se fake phishing emails bhej sakte hain.

f) Server Information Leakage & Files:
   - Server banners (jaise exact Apache 2.4.41 ya PHP version leak).
   - robots.txt aur /.well-known/security.txt file check karta hai.

g) OWASP Top 10 (2021) Mapping:
   - Har test ko OWASP Top 10 categories (A01 se A10) ke sath live map karta hai.


--------------------------------------------------------------------------------
TIER 2: DEEP SCAN (Active Probing — Sirf Verified Owners Ke Liye)
--------------------------------------------------------------------------------
Deep Scan mein target par active checks aur payloads bhejte hain. Isliye ye tabhi 
chalta hai jab user prove kare ki domain uska apna hai.

Iske checks:
1. Reflected XSS Probe:
   - Query parameters (?q=, ?search=) mein safe non-destructive canary token inject 
     karke dekhta hai ki kya input bina escape huye wapas aa raha hai.
2. Open Redirect Check:
   - Login/redirect parameters ko test karta hai ki kahin user ko kisi phishing 
     domain par toh redirect nahi kiya ja sakta.
3. SQL Injection Error Probe:
   - Safe single-quote probe bhej kar check karta hai ki database error syntax leak 
     ho raha hai ya nahi (zero destructive commands).
4. Sensitive File & Admin Panel Exposure:
   - Check karta hai ki kya /.env, /.git/HEAD, /phpinfo.php, ya hidden admin panels 
     public internet par open toh nahi hain.
5. Active CORS Misconfiguration:
   - Fake 'Origin' header bhej kar check karta hai ki kya server kisi bhi unknown 
     origin ko credentials ke sath allow kar raha hai.
6. Rate Limiting Check:
   - Login endpoints par fast requests bhej kar check karta hai ki brute force attack 
     rokne ke liye 429 Too Many Requests response aata hai ya nahi.

3. WHAT IF A USER TESTS GOOGLE.COM? (Abuse & Legal Protection)
================================================================================
Judges ka sabse pehla sawal hota hai: "Agar main aapke tool mein google.com daal 
du toh kya ye Google par attack kar dega?"

CyberShield ka bullet-proof answer aur mechanism:

1. High-Profile Denylist:
   - google.com, apple.com, gov.in, nic.in, aur critical infrastructure domains 
     denylist mein daale gaye hain. Inhe Deep Scan karna impossible hai.

2. Domain Ownership Verification (Google Search Console jaisa model):
   - Agar kisi ko Deep Scan chalana hai, toh use pehle 3 tareeqon mein se kisi 1 se 
     apna ownership verify karna hoga:
     * Method A (DNS TXT): Apne DNS mein 'cybershield-verify=<token>' record add karo.
     * Method B (Well-Known File): Apni site par '/.well-known/cybershield-verify.txt' file banao.
     * Method C (HTML Meta Tag): Apne homepage ke head mein '<meta name="cybershield-verify">' lagao.
   - Jab tak verification pass nahi hoti, Deep Scan execute hi nahi hoga (HTTP 403 Forbidden).

3. Legal Attestation Checkbox:
   - User ko checkbox tick karna padta hai ki: "Main legally attest karta hu ki mere 
     paas is domain ko test karne ki written permission hai under Indian IT Act Section 43/66."

4. Strict Real-Time Multi-Method Verification (Zero Bypass):
   - Koi bhi fake demo ya client bypass button allowed nahi hai. Verification LIVE hoti hai:
     * DNS TXT live lookup
     * .well-known/cybershield-verify.txt HTTPS fetch (SSRF-protected)
     * Homepage HTML <meta name="cybershield-verify"> tag match
   - Fails closed on any timeout, DNS mismatch, or error.
   - Legal attestation server-side audit log maintain hota hai (user, target, timestamp, IP).

4. SECURE YOUR OWN SCANNER (Platform Self-Defense & Anti-SSRF)
================================================================================
Cyber Security projects mein 90% students tab fail hote hain jab judge kehta hai: 
"Main tumhare scanner mein http://127.0.0.1 ya http://169.254.169.254 daal dunga!"

CyberShield ne apne aap ko kaise secure kiya:

1. Anti-SSRF Perimeter Protection:
   - Jab user koi URL daalta hai, hamara system request bhejne se pehle DNS resolve karta hai.
   - Agar IP private network (127.0.0.1, 10.x.x.x, 192.168.x.x, 172.16.x.x) ya cloud 
     metadata IP (169.254.169.254 AWS/GCP/Azure) nikalti hai, toh scanner connection 
     request bhejne se PEHLE hi block kar deta hai (Pre-Connection SSRF Guard).
   - Isse DNS Rebinding attacks bhi fail ho jaate hain.

2. Hostile Response Sanitization:
   - Target website ke response mein agar hacker ne koi malicious script daal rakhi ho, 
     toh hamara platform use pure text mein HTML-escape karta hai taaki hamare report 
     viewer par Stored XSS attack na ho sake.

3. Non-Destructive Safe Payloads:
   - Hum koi DROP TABLE, DELETE, ya system command injection nahi chalate. 
     Sirf syntax anomaly aur harmless canary tokens use hote hain.

5. HUMAN-IN-THE-LOOP & CONFIDENCE LEVELS (Aap Competitors Se Alag Kaise Ho?)
================================================================================
Burp Suite, OWASP ZAP, ya Nuclei se compete karne ke bajaye CyberShield in 3 cheezon 
se stand out karta hai:

1. False Positive Fatigue Khatam Karna:
   - Har finding par ek Confidence Level hota hai:
     * [CONFIRMED]: Cryptographically ya mathematically proven bug (jaise missing header).
     * [LIKELY]: Strong indicator mila hai (jaise error string match).
     * [NEEDS HUMAN VERIFICATION]: Complex logic jise human ko double-check karna chahiye.

2. Honest Testing (No Fake Human Automation Claims):
   - Business Logic flaws, 2-account IDOR, aur race conditions ko koi bot 100% automate 
     nahi kar sakta.
   - CyberShield repetitive probing karke user ko ek "Guided Manual Checklist" deta hai:
     * Example: "IDOR Check: Account A se profile create karo, phir Account B ke 
       session cookie se Account A ki ID access karke dekho."
     * Example: "Race Condition: Turbo Intruder ya curl parallel se simultaneous 
       coupon apply request bhejo."

3. Actionable Remediation (Sirf problem nahi, solution bhi):
   - Har missing header ya flaw ke liye 5 alag-alag server environments ka ready-to-copy 
     code snippet diya gaya hai:
     * Nginx
     * Apache
     * Cloudflare Transform Rules
     * Next.js (next.config.js)
     * Caddy Web Server

6. TWO AUDIENCES & EXPORT CAPABILITIES
================================================================================
Security reports ko do alag log padhte hain, isliye hamare paas dual mode hai:

1. Executive Summary Mode:
   - Company ke CEO, Manager, ya non-technical business owner ke liye aasan English 
     mein ek paragraph ka summary ki unki company ka risk level kya hai aur action 
     items kya hain.

2. Technical Detail Mode:
   - Developers aur SecOps analysts ke liye detailed evidence, request URL, response 
     snippet, CWE numbers, aur code fixes.

3. DevSecOps Export Formats:
   - Copy / Download JSON: Developers ke liye structured data.
   - Executive Markdown: Documentation aur ticketing ke liye.
   - Print / PDF: Management meeting ke liye ready report.
   - SARIF 2.1.0 Export (Static Analysis Results Interchange Format):
     Ye industry-standard format hai. Is file ko direct GitHub Security tab ya 
     CI/CD pipeline mein plug kiya ja sakta hai.
